# Unified Document Extractor — Remove Legacy Files & Streamline Pipeline
 
## Background
 
The current document pipeline has **three overlapping extraction paths**:
1. **`doc_processing.py`** (src/pipelines/) — Legacy orchestrator with hardcoded Titan extractor xlsx patterns, equipment tag maps, and a tiered fallback system (xlsx → LLM → local → CSV fallback)
2. **`local_doc_extractor.py`** (src/pipelines/) — Legacy ACME Cement-specific parser (hardcoded DOCX table parsing for Maintenance/SOP/OEM/RCA documents, plus FMEA/PM Schedule parsers)
3. **`user_doc_extract.py`** (src/source_processing/documents/) — The **correct** unified extractor that reads `doc_types_cfg` from `user_config.yaml` and handles Excel/CSV row-by-row + PDF/DOCX via Bedrock Claude LLM
 
The `run_docs_end_to_end.py` pipeline **already uses `user_doc_extract.py` directly** (line 36-37, 197-201). It does NOT import `doc_processing.py` or `local_doc_extractor.py`. The only reference from `doc_processing.py` to `local_doc_extractor.py` is in the Tier 2b fallback path — which is dead code in the current frontend-triggered flow.
